# 架构说明

## 当前阶段

项目已完成第 8 步：定义完整对局状态。

当前工程是一个浏览器端本地运行的 Vite + TypeScript + 原生 HTML/CSS 应用。项目已拆分出游戏状态模块、基础牌数据模型、完整牌池生成与洗牌模块、玩家状态模块、初始发牌模块、界面渲染模块和事件绑定模块。当前已能初始化一局新对局，包含双方初始手牌、剩余牌山、当前行动方、最后打牌记录、结束结果占位、海底标记和河底标记，但仍不包含摸牌、打牌、计分、AI、胡牌判断或正式界面交互逻辑。

## 根目录文件

### `package.json`

项目 npm 配置文件，声明当前工程为私有前端项目，并配置基础脚本：

- `dev`：启动 Vite 开发服务器。
- `build`：先执行 TypeScript 类型检查，再执行 Vite 生产构建。
- `test`：运行 Vitest 单元测试。

当前开发依赖包括：

- `vite`：前端开发服务器与构建工具。
- `typescript`：类型检查与 TypeScript 支持。
- `vitest`：单元测试框架。
- `jsdom`：为当前 UI 渲染测试提供 DOM 环境。

### `package-lock.json`

npm 依赖锁文件，用于固定依赖解析结果，保证后续开发者安装到一致的依赖版本。

### `tsconfig.json`

TypeScript 配置文件。

职责：

- 使用浏览器 DOM 类型。
- 使用适合 Vite 的 ES 模块与 Bundler 模块解析配置。

### `vite.config.ts`

Vite 配置文件。

职责：

- 提供 Vite 默认构建与开发服务器配置入口。

### `src/game/game-state.ts`

完整对局状态聚合模块。

职责：

- 定义 `GameStatus`，用于表示对局阶段：`not-started`、`player-turn`、`computer-turn`、`ended`。
- 定义 `Actor`，用于统一表示玩家或电脑这两个行动主体。
- 定义 `WinMethod`，为后续荣和、自摸结算记录胡牌方式。
- 定义 `GameEndResult`，为后续和牌结束与流局结束提供统一结果结构。
- 定义 `DiscardRecord`，用于记录最后打出的实体牌和打牌者。
- 定义 `GameState`，聚合页面标题、说明文案、双方玩家状态、剩余牌山、当前行动方、最后打牌记录、结束结果、海底标记和河底标记。
- 导出 `createNewGameState(randomSource?)`，用于创建一局新对局。
- 导出 `createInitialGameState()`，当前作为入口兼容函数，返回一局新对局状态。

当前新对局初始化流程：

- 使用 `createTilePool()` 创建 48 张完整牌池。
- 使用 `shuffleTilePool()` 洗牌，并允许注入 `RandomSource` 以便测试稳定复现。
- 使用 `dealInitialHands()` 为玩家和电脑各发 13 张初始手牌。
- 初始剩余牌山为 22 张。
- 初始 `status` 为 `player-turn`。
- 初始 `currentActor` 为 `player`。
- 初始 `lastDiscard` 与 `endResult` 为 `null`。
- 初始 `isHaitei` 与 `isHoutei` 为 `false`。

当前限制：

- 只负责完整对局状态结构和新对局初始化。
- 尚未实现摸牌、打牌、回合切换、流局推进、胡牌判断、计分或 AI 行动。

- 对局状态模块不依赖 DOM，也不负责 UI 展示。

### `src/game/tile.ts`

基础牌数据模型模块。

职责：

- 定义本项目允许使用的牌类型：索子与三元牌。
- 定义 `SouzuRank`，限制索子只能是一索至九索。
- 定义 `DragonValue`，限制字牌只能是白、发、中。
- 定义 `SouzuTile`、`DragonTile` 和联合类型 `Tile`。
- 导出 `allowedTiles`，作为当前项目唯一允许牌种列表。
- 导出 `tileIds`，提供稳定的牌 ID 列表。
- 导出 `compareTiles()`，用于手牌、测试和后续规则中的确定性排序。
- 导出 `isSameTile()`，用于按稳定 ID 判断两张牌是否为同一种牌。
- 导出 `getTileById()`，用于根据牌 ID 获取对应牌定义。

当前牌 ID 约定：

- 索子使用 `souzu-1` 至 `souzu-9`。
- 三元牌使用 `dragon-white`、`dragon-green`、`dragon-red`。

当前显示顺序：

- 一索至九索。
- 白、发、中。

当前限制：

- 不包含万子、筒子、东南西北风牌或赤宝牌。
- 只定义牌种，不生成四张实体牌，也不负责洗牌。
- 牌池生成、发牌、摸牌和玩家手牌都应复用这里的牌定义与排序规则。

### `src/game/deck.ts`

完整牌池生成与洗牌模块。

职责：

- 基于 `src/game/tile.ts` 导出的 `allowedTiles` 生成完整牌池。
- 定义 `TileCopy`，用于表示某一种牌的实体副本。
- 定义 `RandomSource`，用于抽象洗牌时使用的随机数来源。
- 导出 `createTilePool()`，生成未洗牌的完整牌池。
- 导出 `shuffleTilePool()`，对传入牌池执行非破坏性洗牌并返回新的数组实例。
- 导出 `countTileTypes()`，统计牌池中每种牌出现次数。

当前牌池规则：

- 牌池只包含一索至九索、白、发、中。
- 每种允许牌生成 4 张。
- 完整牌池总数为 48 张。
- 每张实体副本通过 `copyIndex` 标记为第 1 至第 4 张。

当前洗牌规则：

- `shuffleTilePool()` 使用 Fisher-Yates 洗牌算法。
- 默认随机来源为 `Math.random`。
- 调用方可以注入自定义 `RandomSource`，用于测试或未来需要确定性牌山的场景。
- 洗牌不会增加、删除或替换任何牌。
- 洗牌不会修改传入的原始牌池数组。

当前限制：

- 不负责发牌、摸牌或牌山状态管理。
- 不负责玩家状态、回合状态、胡牌判断或计分。
- 后续发牌流程应复用 `createTilePool()` 与 `shuffleTilePool()`，不要在发牌模块中重复实现牌池生成或洗牌算法。

### `src/game/player.ts`

玩家状态模块。

职责：

- 定义 `initialPlayerPoints`，作为玩家与电脑的统一初始点数，目前固定为 100000 点。
- 定义 `MeldType`，目前包含 `chi`、`pon`、`kan`，用于表示吃、碰、杠的副露类型。
- 定义 `Meld`，用于记录一组副露及其包含的实体牌。
- 定义 `PlayerState`，用于描述玩家和电脑共享的状态结构。
- 导出 `createPlayerState()`，用于创建一份新的玩家状态实例。

当前玩家状态字段：

- `hand`：手牌，类型为 `TileCopy[]`。
- `discardPile`：牌河，类型为 `TileCopy[]`。
- `melds`：副露列表，类型为 `Meld[]`。
- `points`：当前点数，初始值为 `initialPlayerPoints`。

当前设计约束：

- 玩家与电脑使用同一个 `PlayerState` 结构。
- 每次调用 `createPlayerState()` 都会创建新的数组实例，玩家和电脑状态互不影响。
- 玩家状态模块不依赖 DOM，也不负责 UI 展示。
- 玩家状态模块不负责发牌、摸牌、打牌、胡牌或计分，只提供这些流程需要操作的状态容器。

后续衔接：

- 第 7 步发牌流程应向 `hand` 写入初始手牌，并保持玩家和电脑手牌相互独立。
- 后续打牌流程应从 `hand` 移除实体牌并加入 `discardPile`。
- 后续副露流程应向 `melds` 追加 `Meld`，并从 `hand` 移除副露使用的牌。
- 后续计分流程应更新 `points`，并继续复用 `initialPlayerPoints` 作为新对局起点。

### `src/game/deal.ts`

初始发牌流程模块。

职责：

- 定义 `initialHandTileCount`，当前固定为 13，表示二人对局中每名角色的初始手牌数量。
- 定义 `dealtPlayerCount`，当前固定为 2，表示初始发牌对象为玩家与电脑。
- 定义 `InitialDealResult`，描述一次初始发牌后的玩家状态、电脑状态和剩余牌山。
- 导出 `sortTileCopies(tileCopies)`，对实体牌数组进行稳定排序。
- 导出 `dealInitialHands(tileWall)`，从传入牌山中完成玩家与电脑的初始发牌。

当前发牌规则：

- 从传入牌山的前 13 张生成玩家手牌。
- 从传入牌山的第 14 至第 26 张生成电脑手牌。
- 发牌后剩余牌山为原始牌山第 27 张及之后的实体牌，当前标准牌池下剩余 22 张。
- 玩家与电脑手牌会按 `src/game/tile.ts` 中的 `compareTiles()` 牌序排序，同一种牌再按 `copyIndex` 排序。
- 发牌函数会创建新的玩家与电脑状态，不修改传入的牌山数组。

依赖关系：

- 依赖 `src/game/deck.ts` 的 `TileCopy` 类型来表示实体牌。
- 依赖 `src/game/player.ts` 的 `createPlayerState()` 与 `PlayerState` 来创建双方状态。
- 依赖 `src/game/tile.ts` 的 `compareTiles()` 来保持手牌排序稳定。

当前设计约束：

- `dealInitialHands()` 不负责创建牌池，也不负责洗牌；调用方应先使用 `createTilePool()` 与 `shuffleTilePool()` 准备牌山。
- 发牌模块不依赖 DOM，也不处理界面展示。
- 发牌模块不负责对局阶段、当前行动方、摸牌、打牌、胡牌或计分。
- 后续完整对局初始化应复用此模块，避免在 `game-state.ts` 或 UI 层重复切牌和排序逻辑。
