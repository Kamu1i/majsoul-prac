# 架构说明

## 当前阶段

项目已完成第 1 步：初始化最小前端工程。

当前工程是一个浏览器端本地运行的 Vite + TypeScript + 原生 HTML/CSS 应用。此阶段只建立运行、构建和测试基础，不包含麻将规则、玩家状态、牌山、计分、AI 或正式界面交互逻辑。

## 根目录文件

### `package.json`

项目 npm 配置文件，声明当前工程为私有前端项目，并配置基础脚本：

- `dev`：启动 Vite 开发服务器。
- `build`：先执行 TypeScript 类型检查，再执行 Vite 生产构建。
- `test`：运行 Vitest 单元测试。

当前开发依赖包括：

- `vite`：前端开发服务器与构建工具。
- `typescript`：类型检查与 TypeScript 支持。
- `vitest`：单元测试框架。

### `package-lock.json`

npm 依赖锁文件，用于固定依赖解析结果，保证后续开发者安装到一致的依赖版本。

### `index.html`

浏览器入口 HTML 文件。

职责：

- 提供页面基础结构。
- 挂载根节点 `#app`。
- 通过 `<script type="module" src="/src/main.ts">` 加载 TypeScript 入口。

### `tsconfig.json`

TypeScript 配置文件。

职责：

- 启用严格类型检查。
- 使用浏览器 DOM 类型。
- 使用适合 Vite 的 ES 模块与 Bundler 模块解析配置。
- 当前不输出编译产物，构建产物由 Vite 负责生成。

### `vite.config.ts`

Vite 配置文件。

职责：

- 提供 Vite 默认构建与开发服务器配置入口。
- 配置 Vitest 的基础测试环境。
- 当前不引入 React、Vue 或其他前端框架插件。

## `src/` 目录

### `src/main.ts`

当前应用入口文件。

职责：

- 引入全局样式。
- 定义并渲染初始化占位文案。
- 将内容挂载到 `index.html` 中的 `#app` 节点。

当前限制：

- 不包含任何麻将规则逻辑。
- 不包含牌山、玩家、计分、AI、胡牌判断或回合状态。
- 后续第 2 步应继续保持入口职责轻量，只负责连接模块。

### `src/styles.css`

当前全局样式文件。

职责：

- 设置页面基础字体、背景和排版。
- 为初始化占位页面提供居中展示样式。

当前限制：

- 只服务最小占位页面。
- 尚未定义正式游戏界面布局。

### `src/main.test.ts`

基础测试文件。

职责：

- 验证 Vitest 测试框架可以运行。
- 验证当前入口导出的占位文案符合预期。

当前限制：

- 只覆盖工程初始化的基础测试。
- 尚未覆盖任何游戏规则或界面交互。

## 后续架构方向

第 2 步应在现有最小工程基础上建立模块化目录结构，建议继续按照实施计划拆分：

- `src/game/`：游戏核心逻辑与状态流转。
- `src/ui/`：页面渲染与用户输入事件。
- `src/main.ts`：保持入口职责，只负责初始化和连接模块。

后续新增规则逻辑时，应继续遵守核心规则逻辑与界面渲染解耦的要求，避免形成单体巨文件。
