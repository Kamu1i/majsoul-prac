# 技术栈推荐

## 推荐技术栈

```text
Vite + TypeScript + 原生 HTML/CSS
```

这是本项目最简单、最健壮、最适合快速实现可运行版本的技术栈。

## 推荐理由

### 1. 项目不需要后端

本游戏是一个单人 PVE 麻将模拟器，核心逻辑可以完全在浏览器中运行，包括：

- 牌山生成
- 发牌、摸牌、打牌
- 玩家与电脑回合切换
- 胡牌判断
- 副露处理
- 点数结算

因此不需要后端服务、数据库或 API。

### 2. TypeScript 更适合规则逻辑

麻将规则中有较多结构化数据和状态判断，例如：

- 牌的类型
- 手牌结构
- 副露状态
- 当前回合状态
- 胡牌条件
- 计分结果

使用 TypeScript 可以让数据结构更清晰，减少因类型错误导致的逻辑问题。

### 3. Vite 轻量且稳定

Vite 适合小型前端游戏项目：

- 配置简单
- 启动速度快
- 开发体验好
- 打包方便
- 不引入过多工程复杂度

### 4. 原生 HTML/CSS 足够完成第一版

当前项目的主要难点在麻将规则和游戏流程，而不是复杂 UI。

第一版可以使用原生 DOM 和 CSS 实现界面，避免过早引入 React、Vue 等框架带来的额外复杂度。

## 推荐项目结构

```text
src/
  main.ts              # 入口
  game/
    tile.ts            # 牌定义
    deck.ts            # 牌山生成与洗牌
    player.ts          # 玩家状态
    game-state.ts      # 对局状态
    rules.ts           # 胡牌判断
    scoring.ts         # 日麻计分
    ai.ts              # 电脑出牌逻辑
  ui/
    render.ts          # 页面渲染
    events.ts          # 用户操作事件
  styles.css
index.html
```

## 最小实现顺序

1. 实现牌与牌山。
2. 实现发牌、摸牌、打牌。
3. 实现玩家和电脑轮流行动。
4. 实现简单电脑出牌逻辑。
5. 实现胡牌判断。
6. 实现流局。
7. 实现基础计分。
8. 优化界面表现。

## 暂不推荐的技术

### 后端服务

不推荐一开始加入 Node.js 服务端、数据库或 API。

原因是当前游戏完全可以作为单机前端应用运行。

### Unity

不推荐一开始使用 Unity。

除非项目目标是强视觉表现、移动端发布或 3D/动画演出，否则 Unity 对当前需求过重。

### React / Vue / Next.js

不推荐第一版直接使用复杂前端框架。

原因是当前 UI 复杂度不高，原生 HTML/CSS 已足够支撑最小可行版本。

如果后续界面变复杂，再升级为 React 或 Vue 会更合适。

## 最终结论

第一版推荐使用：

```text
Vite + TypeScript + 原生 HTML/CSS
```

后续如果 UI 复杂度明显提升，可以升级为：

```text
Vite + TypeScript + React
```
